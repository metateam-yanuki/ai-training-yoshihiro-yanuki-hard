# Day 07 — Human-in-the-Loop（承認フロー・中断・再開）

## 受講者が実装する場所

- `day07/app.py` の `run_with_hitl()`

## 目的

エージェントが重要なアクションを実行する前に人間の確認を挟む仕組みを実装する。LangGraph の `interrupt()` を使った一時停止・再開のパターンを理解し、承認フローを持つ安全なエージェントを構築する。

## ゴール（完了条件）

- ツール実行前に承認プロンプトが表示される
- `n` を入力すると処理が中止され「承認されなかったため処理を中止しました」が返る
- `y` を入力すると処理が続行して最終回答が返る
- `--auto-approve` でテスト・CI 環境でも動作確認できる
- `--thread-id` で中断後に再開できる（チェックポイント永続化）

## 機能要件

### コマンド

- `python -m day07.app` で起動できること

### 必須オプション

- `--query`：エージェントへの入力テキスト（文字列、必須）

### 任意オプション

- `--thread-id`：チェックポイントを識別するID（デフォルト: `default`）
- `--auto-approve`：承認プロンプトを自動で `y` にする（フラグ、テスト用）
- `--region`：AWSリージョン
- `--model-id`：BedrockのモデルID

### 承認フローの仕様

1. エージェントがツール実行を検討する
2. ツール実行ノードの直前で `interrupt()` を呼び出す
3. 標準入力から「このアクションを実行してよいか？[y/n]: 」を表示して確認を求める
4. `y` → 続行、`n` → 中止メッセージを返す
5. チェックポイントは `hitl.db` に保存する

### 終了コード

- 正常終了（承認/中止どちらも）：`0`
- 入力不備：`2`
- 実行失敗：`1`

## 実装タスク

1. LangGraph で承認が必要なノードを定義する
2. `interrupt()` をツール実行ノードの直前に追加する
3. 承認プロンプト（`[y/n]`）を標準入力から受け取るロジックを実装する
4. 承認された場合と中止の場合で分岐するエッジを実装する
5. `SqliteSaver` でチェックポイントを永続化する
6. `auto_approve=True` のときは `input()` をスキップして自動承認する

## 実行方法

### 必要な環境変数

```bash
cp .env.example .env
export AWS_PROFILE=training
export AWS_REGION=ap-northeast-1
export BEDROCK_MODEL_ID=anthropic.claude-haiku-4-5-20251001-v1:0
```

### 承認フローの動作確認

```bash
# 承認する場合（プロンプトで y を入力）
python -m day07.app --query "重要なドキュメントを削除してください" --thread-id t1

# 自動承認（テスト用）
python -m day07.app --query "調査レポートを作成してください" --thread-id t2 --auto-approve
```

### 中断・再開の動作確認

```bash
# 1回目: ターミナルで n を入力して中断
python -m day07.app --query "データを処理してください" --thread-id resume-test

# 2回目: 同じ thread-id で再実行して続きから再開
python -m day07.app --query "データを処理してください" --thread-id resume-test --auto-approve
```

### 期待する出力例

```
このアクションを実行してよいか？[y/n]: n
承認されなかったため処理を中止しました
```

```
このアクションを実行してよいか？[y/n]: y
（最終回答テキスト）
```
